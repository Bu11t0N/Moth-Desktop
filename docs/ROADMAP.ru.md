# RoadMap Moth Desktop

Дата: 13 ноября 2026. Рабочая база: **Desktop 0.3.2**, Android **1.0.2**.

Сравнение выполнено по Android `main` на коммите [36dfa07][android] и Desktop
[4ee172f][desktop]. Сведения ниже описывают код на этих ревизиях; очередность
этапов — предлагаемый план развития. Реализованное и проверенное в Desktop
перечислено в [STATUS.md](STATUS.md).

Цель: перенести привычные возможности мобильного Мотылька, получить надёжный
клиент Windows и затем Linux. Сохраняем Rust, Tauri и отдельные системные службы.
Общие форматы, настройки и политики должны подходить обеим ОС.

## От чего отталкиваемся

В Desktop уже работают системный TUN Windows, служба с проверкой подлинности,
защищённое хранение DPAPI, импорт VLESS/Trojan и Base64-списков, выбор сервера,
HTTPS-проверки, трей, сохранение подключения после крестика и отключение через
«Выход». Для TCP, WS, gRPC, XHTTP, TLS/Reality/Vision есть модели и проверки
конфигураций. Нативные испытания подтверждают конкретные тестовые сценарии;
совместимость со всеми провайдерами и транспортами требует отдельной матрицы.

Остаются крупные пробелы: подписки по HTTPS, восстановление сети, kill switch,
маршрутизация, другие протоколы, полноценные настройки, статистика, резервные
копии, обновления и работающая Linux-версия.

### Что показало изучение Android

При переносе ориентируемся на код, журнал изменений и тесты вместе.

- В README Android AmneziaWG ещё указан как неподдерживаемый. В коде, тестах
  и журнале 1.0.0 уже есть **частичная** поддержка: `wireguard://`, `.conf`,
  `vpn://`, Jc/Jmin/Jmax и I1–I5. Допускаются S1–S4 = 0 и стандартные H1–H4 = 1–4;
  варианты с дополнением пакетов или своими заголовками отвергаются.
  Это отдельная строка совместимости, а не полная поддержка AWG.
  [A2], [A3], [A4]
- Проверки доступности в Android сохраняют результаты в приватном файле;
  при переносе нужны давность результата и привязка к реальной сети. [A5]
- Страница соединений Android использует API libbox для списка и закрытия
  потоков. Desktop использует отдельные процессы ядер: получение этих данных
  и привязка к приложениям требуют отдельной реализации. [A6], [A7]
- У подписок есть режим обновления **только через VPN**, включая случай, когда
  пользовательские правила направляют адрес провайдера напрямую. Для этого
  в Android есть отдельный путь загрузки и E2E-тест. [A8], [A9]

## Очерёдность работ

Версии увеличиваем последовательно: **0.3.3, 0.3.4, 0.3.5…**. Один этап может
занять несколько небольших выпусков. Номера после ближайшего выпуска и даты
фиксируем при подготовке конкретной версии, исходя из результатов приёмки.

### R0. Установка, обновление и диагностика — ближайший приоритет

Первый кандидат для **0.3.3** — диагностический экран и безопасное обновление
уже установленной службы. Завершённые части можно выпускать отдельно.

- [ ] Показать версии GUI, службы, ядер и совместимость протокола управления.
- [ ] Согласовать сведения о возможностях с реальным состоянием службы.
- [ ] Добавить понятные ошибки по стадиям: служба, ядро, адаптер, DNS, проверка.
- [ ] Добавить ограниченный журнал с экспортом и предварительной очисткой
  URL подписок, адресов, паролей, UUID, ключей и идентификаторов устройства.
- [ ] Подготовить установку, обновление и удаление без ручной очистки Program Files.
- [ ] Обновлять GUI/службу/ядра согласованно, сохранять данные и иметь откат.
- [ ] Добавить «Подключить» в трей для выбранного сервера.

**Готово, когда:** чистая установка, обновление с 0.3.1/0.3.2, неудачное
обновление и откат проверены на VM; профили сохраняются; обычный пользователь
управляет VPN без постоянного запуска GUI от администратора; диагностический
экспорт не содержит секретов. Ключи подписи готовим отдельно от исходников.

### R1. Устойчивое и защищённое подключение — P0

- [ ] Восстанавливать связь после Wi-Fi ↔ Ethernet, потери интернета, сна,
  смены адреса/шлюза и перезапуска службы согласно сохранённому намерению пользователя.
- [ ] Различать «Нет сети», «Подключаем», «Переподключаем», «Трафик заблокирован»
  и «Ошибка»; подтверждать состояния из службы.
- [ ] Периодически проверять фактическую работоспособность туннеля.
- [ ] Реализовать kill switch средствами Windows WFP, с сохранением блокировки
  при падении ядра или службы и явным действием восстановления доступа.
- [ ] Зафиксировать DNS/IPv6-политику, проверить утечки и совместимость сетей
  IPv4-only, IPv6-only и dual stack; обработать несколько адресов VPN-сервера.
- [ ] Настроить DNS/bootstrap DNS, IPv6, MTU, таймауты и интервал проверок.
- [ ] Добавить независимые настройки автозапуска GUI свёрнутым в трей и
  подключения после входа пользователя, когда доступно его защищённое хранилище.

**Предлагаемая политика по умолчанию:** kill switch блокирует внешний трафик
при неожиданном разрыве активного VPN; обычные «Отключить» и «Выход» снимают
принадлежащую Moth блокировку. Исключения для DIRECT и приложений требуют
отдельной явной настройки. Окно можно закрывать, сохраняя подключение, как в 0.3.2.

**Готово, когда:** на VM проверены падение обоих ядер и службы, отмена запуска,
сон, смена сети, повторное подключение и восстановление после перезагрузки.
Внешние контрольные точки подтверждают блокировку и отсутствие заявленных
утечек. Очистка затрагивает только объекты Moth и сохраняет изменения DHCP/пользователя.

### R2. Подписки — основной перенос пользовательского сценария Android

- [ ] Добавлять несколько HTTPS-подписок; отделить их от «Моих серверов».
- [ ] Сохранять выбор, избранное и принадлежность серверов при обновлении.
- [ ] Обновлять вручную и по расписанию; показывать время и результат обновления.
- [ ] Защитить обновление от гонок: удалённая подписка не появляется снова,
  скачивание старого URL не перезаписывает отредактированный источник.
- [ ] Показывать лимит/остаток трафика, дату окончания, предупреждения и ссылки
  провайдера, когда он действительно передаёт эти данные.
- [ ] Поддержать User-Agent, случайный идентификатор установки и необязательные
  данные устройства с выбором конкретных подписок-получателей.
- [ ] Реализовать обновление подписки только через активный VPN.
- [ ] Ограничить размеры, время, вложенные источники и перенаправления;
  заголовки устройства разрешать только утверждённому HTTPS origin.

**Готово, когда:** ошибки сети не уничтожают рабочий список, обновление не
обрывает используемый профиль, а VPN-only загрузка не переходит напрямую
при остановке туннеля или совпадении с пользовательским правилом DIRECT.
Реальные идентификаторы железа не нужны: используем случайный идентификатор
установки с прозрачным выбором получателей.

### R3. Менеджер серверов, проверки и автовыбор

- [ ] Поиск, избранное, сортировки, группы и фильтры по названию/протоколу/источнику.
- [ ] Пакетные HTTPS/TCP-проверки с ограничением параллелизма и отменой.
- [ ] Хранить результат, метод, давность и сетевой контекст; отличать ошибку,
  отсутствие проверки и отмену. HTTPS-задержку и TCP-доступность показывать отдельно.
- [ ] Автовыбор при подключении и переключение после подтверждённых сбоев;
  ручной выбор пользователя сохраняет приоритет.
- [ ] Проверять кандидатов, сохраняя текущий туннель; ограничить частоту
  повторов и переключений, учитывать восстановление текущего сервера.
- [ ] Разделить выбор и результаты для Wi-Fi/Ethernet и смены конкретной сети.
- [ ] Добавить структурированный редактор профиля, копирование ссылки, QR,
  импорт QR из изображения и при необходимости камеры.
- [ ] Поддержать ссылки Moth/v2rayNG/Happ/Hiddify/sing-box с подтверждением импорта.

**Готово, когда:** недоступные и непроверенные серверы различимы, отмена не
стирает последнее измерение, переключение сети помечает старые результаты,
а автовыбор не создаёт бесконечный цикл переподключений. QR/ссылки с ключами
показываются только по явному действию и не попадают в журнал.

### R4. Форматы и протоколы — перенос волнами

- [ ] Clash YAML/JSON, sing-box JSON, Xray JSON и ограниченные вложенные списки.
- [ ] Предпросмотр импорта: принятые профили, неподдерживаемые параметры,
  причины отказов и судьба правил/DNS/inbounds из исходного файла.
- [ ] Отдельно спроектировать Xray balancer: это составной профиль, требующий
  модели и проверок, а не только разбора одного outbound.
- [ ] Довести матрицу текущих VLESS/Trojan: реальные TLS/Reality/Vision,
  WS/gRPC/XHTTP, разные SNI/Host, ошибки сертификатов, IPv4/IPv6.
- [ ] Первая волна: VMess, Shadowsocks, Hysteria2, TUIC и HTTPUpgrade.
- [ ] Следующие волны: AnyTLS, Hysteria v1, SOCKS5/HTTP(S), WireGuard, SSH,
  ShadowTLS — по потребности пользователей и доступности в закреплённых сборках ядер.
- [ ] AmneziaWG: сначала определить требуемый вариант совместимости и ядро;
  частичную поддержку Android обозначать со всеми её ограничениями.

**Архитектурная работа:** выбирать безопасный путь исполнения для каждого
протокола: нативный outbound sing-box либо текущий мост к Xray. Проверять
привязку исходящих соединений и реальные возможности сборки ядра. Параметры
профиля проходят типизированную валидацию; служба сохраняет фиксированные
команды и защищённые пути исполнения.

**Готово для каждого протокола отдельно, когда:** есть положительные и
отрицательные фикстуры, проверка ядром и E2E через системный TUN с реальным
рукопожатием, DNS и поддерживаемым TCP/UDP. Разбор формата сам по себе не
завершает поддержку протокола. Неподдерживаемые параметры безопасности
не отбрасываются молча.

- [ ] Два режима по приложениям: выбранные обходят VPN / только выбранные

**Готово, когда:** тестовые приложения и домены действительно используют
заданный путь; новые процессы и правила не создают обход блокировки; пользователь
видит действующие исключения. Определение приложений и применение правил
реализованы на уровне ОС, отдельно для Windows и Linux.

### R7. Резервные копии и перенос с Android

- [ ] Версионированный переносимый архив с шифрованием паролем и предпросмотром.
- [ ] Импорт Android `moth-backup`: подписки, совместимые серверы, избранное,
  общие правила и поддерживаемые настройки.
- [ ] Отчёт о несовместимых полях; Android package names не становятся
  правилами для Windows EXE автоматически.
- [ ] Преобразование сетевых выборов и идентификаторов с сохранением связей.
- [ ] Отдельный выбор переноса идентификатора устройства; новый Desktop
  по умолчанию получает собственный случайный ID.
- [ ] Экспорт совместимых данных обратно на Android после проверки формата.

**Готово, когда:** обычная и зашифрованная Android-копии проходят набор
межплатформенных фикстур, неверный пароль/повреждение не меняют библиотеку,
восстановление атомарно и имеет откат. Локальное хранение остаётся DPAPI
в Windows и системным секретным хранилищем в Linux.

### R8. Настольный интерфейс и доставка обновлений

- [ ] Светлая, тёмная и системная темы; чисто чёрная — пользовательский выбор.
- [ ] Русский/английский, системный язык, доступность с клавиатуры и диктора.
- [ ] Обучение: служба, подписка, подключение, трей и состояние блокировки.
- [ ] Системные уведомления о подключении, сбое, подписке и обновлении.
- [ ] Действия и выбор сервера в трее, компактный режим по необходимости.
- [ ] Анимации мотылька, соответствующие реальному состоянию и настройке
  уменьшения движения; проверки DPI 100/150/200 %.
- [ ] Каналы release/beta, список изменений и добровольная установка обновления.
- [ ] Проверять подлинность обновления, версию и совместимость компонентов;
  предусмотреть откат и хранение ключей вне репозитория.
- [ ] Контроль CPU/RAM и частоты опросов в фоне, особенно на ноутбуках.

**Готово, когда:** обновление и удаление проверены на чистой системе,
сохраняются данные, после сна/перезапуска нет дублирующихся окон и значков,
клавиатура и масштабирование проходят нативную приёмку. Автозагрузка и
установка обновлений имеют явную пользовательскую настройку.

### R9. Linux — отдельный этап с ранней подготовкой

Общие модели настроек, библиотеку профилей, форматы и политики из R0–R5 сразу
держим вне Tauri и Windows API. Начальная Linux-альфа возможна с набором:
подписки, подключение/отключение, DNS/IPv6-политика, блокировка и восстановление.

- [ ] systemd-служба, локальный IPC с проверкой UID и авторизацией управления.
- [ ] Хранилище Secret Service/keyring и миграции данных.
- [ ] TUN и привязка исходящих сокетов, nftables и интеграция DNS.
- [ ] Начальная матрица из ТЗ: Ubuntu 24.04 LTS с systemd; Fedora следующим шагом.
- [ ] Проверки NetworkManager/systemd-resolved, сна, смены сети и перезапуска службы.
- [ ] GNOME/KDE, X11/Wayland; доступность трея и надёжный способ вернуть окно.
- [ ] Установка/обновление/удаление `.deb`, затем `.rpm`; GUI работает с обычными правами.
- [ ] Та же сетевая приёмка и правила честного отображения состояний, что у Windows.

**Готово, когда:** чистая Linux VM устанавливает приложение, сохраняет секреты,
подключается к реальному серверу, восстанавливается после смены сети и корректно
удаляет свои правила/службу. Сборка общих Rust crates остаётся отдельной проверкой.

### R10. Расширенные возможности

- [ ] LAN sharing: явный HTTP/SOCKS-прокси, выбор интерфейса, авторизация,
  ограничение клиентов, понятные адреса подключения и обработка занятого порта.
- [ ] TLS fragmentation, UDP noise и mux — выключены по умолчанию,
  с отдельной матрицей протоколов, производительности и совместимости.
- [ ] Корпоративные/пользовательские центры сертификации с явным управлением
  доверием, сохраняя проверку сертификатов. Android уже имеет интеграцию CA. [A18]
- [ ] При подтверждённой потребности — второй UI на Iced поверх общих модулей.

**Готово, когда:** новые listeners имеют явную область доступности, закрываются
при отключении и не открывают доступ к управляющему API; расширенные настройки
проходят реальные сетевые тесты. LAN-прокси и раздача интернета/NAT — разные
задачи с отдельными критериями.

## Зависимости и выпуск первой Windows-беты

Основная очередь: **R0 → R1 → R2 → R3 → R4/R5**. Для статистики R6 нужны
API ядер и определение процессов; для полной миграции R7 — стабильные модели
подписок и правил. Подготовку Linux ведём через общие интерфейсы с R0, реализацию
Linux запускаем после устойчивой основы Windows и подписок. Работы R8 можно
включать небольшими порциями в эти выпуски.

Условия первой публичной Windows-беты:

- Установка, обновление с откатом и защищённое хранение проходят приёмку.
- Kill switch, восстановление сети и заявленная DNS/IPv6-политика подтверждены
  внешними проверками на VM, включая падение ядра/службы.
- Работает основной сценарий HTTPS-подписки и опубликована проверенная
  матрица протоколов/транспортов.
- Пройдены нативные сценарии GUI/трея, DPI и базовой доступности; доступны RU/EN.
- Выполнен обзор безопасности локального IPC, listeners, импорта и обновлений;
  подготовлены подписи, исходники и лицензионные материалы.
- Текущие ограничения перечислены явно. Номер выпуска сам по себе не означает
  готовность беты или наличие функции.

Для каждого рабочего пункта перед реализацией фиксируем пользовательский
сценарий, модель/IPC, поведение при отказе, миграцию данных, критерии приёмки
и способ отката. После выполнения обновляем STATUS и этот RoadMap.
