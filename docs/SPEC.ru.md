# Техническое задание: Moth Desktop

Статус: принято в работу по поручению пользователя 12 ноября 2026.
База исследования: Android Moth 1.0.2, main 36dfa07da6b813493863ac48eadf4a0e67798ad1.

## Цель и платформы

Создать открытый настольный VPN-клиент Moth. Первый выпуск: Windows 11 x64.
Следующая платформа: Linux x64, первоначально Ubuntu 24.04 LTS с systemd, далее Fedora.
Windows 10, ARM64, другие init/DNS-системы, Flatpak и macOS вне исходной матрицы.
Разработка и релизы независимы от Bu11t0N/Moth. Один настольный репозиторий для обеих ОС.

## Стек и границы

- Rust: доменная логика, импорт, хранение, контроллер соединения, системная служба.
- Tauri 2, TypeScript, CSS: интерфейс; GUI работает без административных прав.
- sing-box и Xray: протоколы и обработка трафика, без самостоятельного переписывания на Rust.
- Версии ядер и необходимые патчи фиксируются после проверки настольной совместимости.
- Доменная логика не зависит от GUI; возможный Iced — будущий адаптер, без второго GUI в MVP.

## Пользовательские требования

1. Добавление подписок и собственных серверов, подтверждение импорта, понятные ошибки.
2. Выбор сервера, избранное, реальная проверка доступности, подключение/отключение.
3. Системный TUN, DNS внутри туннеля, предусмотренная политика IPv6.
4. Kill switch с явно описанной политикой сбоев и отдельным действием снятия блокировки.
5. Восстановление после смены сети, сна/пробуждения и перезапуска службы.
6. Трей, независимость подключения от окна, автозапуск по выбору пользователя.
7. Журнал без секретов, понятные ошибки, статистика только по реальным данным.
8. Добровольные обновления с проверкой подписи и защитой от отката.
9. Русский интерфейс в первой preview; русский и английский к публичной бете.
10. Совместимость импорта с Android; выборочная миграция настроек и переносимые резервные копии.

Пакет приложения Android и HWID не переносятся как идентификатор компьютера.
Ограничения протоколов и доступность функций указываются явно для каждой версии.

## Этапы и критерии приёмки

### M0 — основание и preview

- Cargo workspace; отдельные доменная, платформенная и Tauri-части.
- Импорт URI VLESS/Trojan и Base64 без загрузки сетевых подписок.
- Проверка UUID, TLS/Reality, транспорта; ошибки не содержат секретов.
- Дедупликация, выбор и удаление, атомарный импорт.
- Хранение Windows DPAPI; UI получает только безопасные summaries.
- Интерфейс работает без сетевого туннеля и прямо сообщает отсутствие защиты.
- Rust-тесты, Windows сборка, CI с проверкой Linux общих crates.

### M1 — ядра и служба Windows

- Определить версии/хэши sing-box и Xray и отделить нужные Android-патчи.
- Сборка/доставка доверенных ядер; тесты с `xray run -test` и `sing-box check`.
- Windows Service, аутентифицированный local IPC, авторизация клиента, фиксированные команды.
- Приватные конфиги вне командной строки, ограниченные права к файлам, очистка временных секретов.
- Настоящий TUN на изолированной VM, корректное отключение и повторное подключение.
- Исключить routing loops, закрыть управляющие listeners от LAN.

### M2 — безопасность и восстановление

- Утверждённые IPv4/IPv6/DNS-политики и автоматические проверки утечек.
- Kill switch на системном уровне: падение ядра, службы, GUI; не только strict_route.
- Восстановление изменённых DNS/маршрутов с учётом параллельных изменений ОС.
- Сон, смена Wi-Fi/Ethernet, потеря сети, несколько адаптеров, конфликт с другим VPN.
- Определённая политика persistent block и ручное восстановление сети.
- Закрытие окна не меняет выбранную политику VPN; показ правдивого состояния после открытия.

### M3 — первая бета

- HTTPS-подписки: ограничения размеров/редиректов/таймаутов, device headers не уходят чужим хостам.
- Дополнительные форматы и протоколы по опубликованной матрице совместимости.
- Автовыбор, базовые правила маршрутизации, трей, установщик и деинсталляция службы.
- Ключи подписи хранятся вне Git; обновления GUI/службы/ядер согласованы и проверены.
- Тест чистой установки/обновления/удаления, доступность клавиатурой, масштаб 100/150/200%.
- Публичная бета только после M1/M2; M0 не позиционируется как готовый VPN.

### L1 — Linux

- systemd-служба, авторизация локального клиента, секретное хранилище пользователя.
- TUN, nftables, интеграция DNS с systemd-resolved/NetworkManager в объявленной матрице.
- Проверка X11/Wayland, GNOME/KDE, установка .deb; .rpm после отдельной валидации.
- Те же сетевые критерии M2. AppImage не заменяет установку привилегированной службы.

## Тестовая стратегия

Доменная логика: URI/Base64, ошибочные и неподдерживаемые параметры, пределы размера,
согласованность конфигов, миграции и библиотека. Windows: DPAPI, атомарная перезапись,
повреждение/другая учётная запись. GUI: навигация, диалоги, ошибки, отсутствие ложного VPN.
Реальные сетевые испытания — отдельные Windows/Linux VM, без изменения сети хост-компьютера.
CI с обычными GUI/модульными проверками не считается доказательством отсутствия утечек.
